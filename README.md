# PostgreSQL + Python — Users & Orders

Учебный проект по работе с PostgreSQL через Python.

## Возможности

- Подключение к PostgreSQL с помощью `psycopg2`.
- Создание связанных таблиц `users` и `orders`.
- Добавление пользователей с проверкой уникальности email.
- Добавление заказов с уникальными UUID.
- Защита от повторного создания заказа.
- Подсчёт суммы заказов каждого пользователя через `LEFT JOIN`, `SUM` и `GROUP BY`.
- Транзакции и обработка ошибок.
- Каскадное удаление заказов при удалении пользователя.

## Технологии

- Python 3
- PostgreSQL
- psycopg2-binary
- python-dotenv

## Установка и запуск

### 1. Создать базу данных

Установить и запустить PostgreSQL, затем создать базу:

```sql
CREATE DATABASE test;
```

### 2. Создать виртуальное окружение

```bash
python3 -m venv venv
source venv/bin/activate
```

Для Windows команда активации отличается.

### 3. Установить зависимости

```bash
python -m pip install -r requirements.txt
```

### 4. Настроить подключение

Скопировать `.env.example` в `.env`:

```bash
cp .env.example .env
```

Указать параметры локального сервера:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=test
DB_USER=user
DB_PASSWORD=
```

При необходимости заменить пользователя и пароль на свои.

### 5. Запустить программу

```bash
python main.py
```

При первом запуске программа создаёт таблицы, если они отсутствуют.

Для добавления демонстрационных пользователей и заказов:

```bash
python main.py --seed
```

Повторный запуск с `--seed` не создаёт дубликаты демонстрационных записей.

## Тестирование

Интеграционные тесты проверяют повторные вставки, конфликты и валидацию суммы:

```bash
python -m unittest -v
```

Тестам нужно подключение к PostgreSQL и право создавать временные таблицы в базе. Тесты создают свои данные во временных таблицах и откатывают транзакцию после каждой проверки.

## Особенности реализации

- `users.id` и `orders.id` — внутренние первичные ключи.
- `users.email` — уникальный идентификатор учётной записи.
- `orders.order_uid` — уникальный UUID заказа.
- `ON DELETE CASCADE` — автоматическое удаление заказов при удалении пользователя.
- `Decimal` — точная работа с денежными значениями.
- `ON CONFLICT` — обработка повторных вставок.

Для уже созданной таблицы ограничение на `NaN` можно добавить один раз через pgAdmin. Если в таблице уже есть такие суммы, сначала исправьте их.

```sql
ALTER TABLE public.orders
    ADD CONSTRAINT orders_amount_not_nan CHECK (amount <> 'NaN'::numeric);
```

Файл `.env` с реальными параметрами подключения не публикуется в GitHub.
